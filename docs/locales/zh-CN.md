## 🚀 代表性开源项目

```
+-----------------------------------------------------------------------------+
| 项目名称      | 开发语言  | 项目定位与功能                                  |
+-----------------------------------------------------------------------------+
| wave-mesh     | Rust      | 基于零拷贝的组播网络音频总线守护进程            |
| synth-core    | C++20     | 采用 SIMD 向量优化的复音模块化 DSP 合成器引擎   |
| jitter-guard  | Rust / C  | 微秒级 PTPv2 时钟漂移与网络抖动监测 CLI 工具    |
| dsp-bench     | Zig / C   | 跨架构 IIR/FIR 滤波器单采样周期效率基准评测工具 |
+-----------------------------------------------------------------------------+
```

### 1. `wave-mesh`
- **系统架构**: 在标准千兆本地以太网中无损传输 64 通道 24-bit/96kHz 音频流的高性能异步零拷贝守护进程。
- **关键特性**: 环形缓冲区共享内存传输、微秒级时钟漂移补偿抖动缓冲层，提供原生 PipeWire 与 JACK 桥接适配器。
- **技术栈**: Rust, Linux `AF_PACKET`, `epoll`, PipeWire SPA.

### 2. `synth-core`
- **系统架构**: 面向音频插件宿主及嵌入式 Eurorack 模块化合成器的实时 DSP 库。
- **关键特性**: 带限振荡器波形生成（BLIT/BLEP）、过采样无延迟反馈（ZDF）滤波器，严格保证音频执行线程内零堆内存动态分配。
- **技术栈**: C++20, AVX2 / ARM NEON SIMD 内建指令, CMake.

### 3. `jitter-guard`
- **系统架构**: 被动监听 IEEE 1588 PTP 数据包及网卡硬件时间戳（`SO_TIMESTAMPING`），精确定位数据包时延变异（PDV）的遥测工具。
- **关键特性**: TUI 终端实时图形化展示、长周期抖动监测 JSONL 结构化导出、时钟失步预警触发机制。
- **技术栈**: Rust, `crossterm`, Linux Socket Timestamping API.

### 4. `dsp-bench`
- **系统架构**: 在多样化 CPU 架构上评估通用音频 DSP 算法单采样点所需时钟周期（Cycles-per-sample）的轻量基准工具。
- **关键特性**: 原生支持 x86_64、aarch64 与 riscv64，直连硬件性能计数器。
- **技术栈**: Zig, C99, GNU Make.

## 📐 工程理念

1. **确定性执行高于一切**: 在实时音频处理中，迟到的数据就是损坏的数据。内存动态分配、互斥锁与阻塞式系统调用严禁出现在音频渲染主循环中。
2. **显式设计优于隐式推断**: 极致性能绝非依靠事后修补。注重缓存局部性的内存布局、结构体紧凑对齐以及清晰的数据所有权才是高吞吐低延迟的基石。
3. **坚持基准测量，拒绝臆想**: 绝不盲信编译器的自我发挥，每一次架构演进与代码重构均需经由硬件计时器、周期计数器及 eBPF 追踪数据的验证。
4. **简洁孕育高韧性**: 复杂的协议往往在复杂的现实物理环境中率先崩溃。保持协议头与封装结构的极致极简，系统才能在恶劣网络与异常供电下稳如磐石。
