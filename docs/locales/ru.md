# Юджин Пак / Eugene Park (@znbobziz-ship-it)

> Системный инженер, специализирующийся на сетевом аудио с ультранизкой задержкой, ядрах Linux жесткого реального времени и детерминированной DSP-инфраструктуре.

Я проектирую и реализую программное обеспечение, работающее в непосредственной близости к аппаратным таймерам и физическим сетевым интерфейсам. Мой фокус сосредоточен на неблокирующей синхронизации (*lock-free*), сериализации пакетов без лишнего копирования (*zero-copy*) и графовых аудиодвижках, где недопустима потеря даже одного семпла.

---

## 🧭 Профиль и Область Интересов

- **Специализация**: Распределенная передача аудио сверхнизкой задержки, прошивки для встроенных DSP, программирование систем жесткого реального времени.
- **Ядро и ОС**: Linux с патчем `PREEMPT_RT`, графовые подсистемы PipeWire / JACK, внутренняя архитектура драйверов ALSA.
- **Сетевые протоколы и синхронизация**: Протокол точной синхронизации времени IEEE 1588 PTPv2, AES67, RTP/RTSP, широковещательная рассылка через raw-сокеты.
- **Текущие исследования**: Векторизованные DSP-алгоритмы на архитектурах RISC-V RVV 1.0 и ARM NEON, неблокирующие очереди SPMC без ожидания (*wait-free*).

## 🚀 Ключевые Проекты с Открытым Исходным Кодом

```
+-----------------------------------------------------------------------------+
| ПРОЕКТ        | ЯЗЫК      | НАЗНАЧЕНИЕ                                      |
+-----------------------------------------------------------------------------+
| wave-mesh     | Rust      | Сетевой аудиомаршрутизатор на базе zero-copy    |
| synth-core    | C++20     | Полифонический модульный DSP-синтезатор с SIMD  |
| jitter-guard  | Rust / C  | Консольный монитор джиттера и дрейфа PTPv2 (мкс)|
| dsp-bench     | Zig / C   | Кроссплатформенный бенчмарк IIR/FIR-фильтров    |
+-----------------------------------------------------------------------------+
```

### 1. `wave-mesh`
- **Архитектура**: Асинхронный аудиодемон без копирования данных в памяти (*zero-copy*), передающий 64 канала с качеством 24 бит/96 кГц по стандартным гигабитным сетям Ethernet без потерь.
- **Особенности**: Кольцевые буферы в разделяемой памяти, адаптивный буфер джиттера с микросекундной компенсацией дрейфа и нативные модули сопряжения для PipeWire и JACK.
- **Стек**: Rust, Linux `AF_PACKET`, `epoll`, PipeWire SPA.

### 2. `synth-core`
- **Архитектура**: Модульная библиотека DSP реального времени, созданная для хостов аудиоплагинов и аппаратных модулей Eurorack.
- **Особенности**: Генераторы с ограниченной полосой пропускания (BLIT/BLEP), фильтры с обратной связью без задержки (ZDF) с передискретизацией и строгое отсутствие динамических выделений памяти в аудиопотоке.
- **Стек**: C++20, интринсики SIMD AVX2 / ARM NEON, CMake.

### 3. `jitter-guard`
- **Архитектура**: Инструмент пассивного сбора телеметрии пакетов IEEE 1588 PTP и аппаратных меток времени сетевой карты (`SO_TIMESTAMPING`) для измерения вариации задержки пакетов (PDV).
- **Особенности**: Интерактивный TUI-интерфейс в терминале, экспорт данных в JSONL для долгосрочного анализа трендов и раннее оповещение о расхождении фазы часов.
- **Стек**: Rust, `crossterm`, API Linux Socket Timestamping.

### 4. `dsp-bench`
- **Архитектура**: Легковесная консольная утилита, оценивающая количество процессорных тактов на один семпл при вычислении стандартных фильтров на различных процессорах.
- **Особенности**: Поддержка архитектур x86_64, aarch64 и riscv64 с прямым доступом к аппаратным счетчикам циклов.
- **Стек**: Zig, C99, GNU Make.

## 📐 Инженерные Принципы

1. **Детерминизм выполнения превыше всего**: В обработке аудио в реальном времени запоздавшие данные равносильны поврежденным. Динамическое выделение памяти, блокирующие мьютексы и системные вызовы ввода-вывода никогда не должны присутствовать в цикле рендеринга звука.
2. **Явные решения вместо неявных допущений**: Производительность невозможно внедрить как заплатку на финальном этапе. Оптимальное размещение структур в кэш-памяти и строгое разграничение владения данными закладываются в архитектуру с самого начала.
3. **Измерять, а не предполагать**: Никакие догадки компилятора не принимаются на веру. Каждое решение по рефакторингу опирается исключительно на показания аппаратных счетчиков циклов, таймеров и трассировку eBPF.
4. **Устойчивость через простоту**: Избыточно усложненные протоколы первыми отказывают при нестабильном сетевом соединении или сбоях питания. Только минималистичные и модульные пакетные структуры сохраняют стабильность в жестких полевых условиях.
